# Ledger — 本地离线的美股交易记录

纯 H5 单页应用。记录每一笔买卖的**时间、股数、价格、手续费**，按 **FIFO** 自动推导持仓成本、已实现盈亏、浮动盈亏和交易统计。

- **完全离线** — Service Worker 预缓存全部资源，装机后断网照常用
- **不联网** — 除首次安装外不发任何网络请求，行情价格手动填写
- **数据只在本机** — IndexedDB，无账号、无后端、无统计埋点
- **可装到 iPhone 主屏** — 添加到主屏后是独立 App，且存储不受 Safari 的 7 天清理策略影响
- **深色 / 浅色主题** — 设置里可以选跟随系统、强制浅色、强制深色
- **零依赖** — 没有框架、没有构建步骤，4 个文件

## 文件

| 文件 | 说明 |
|---|---|
| `index.html` | 页面结构 + 全部样式 |
| `app.js` | 数据层（IndexedDB）、FIFO 推导、渲染、代码搜索、导入导出 |
| `stocks.js` | 299 支常用美股的代码 / 中文名 / 英文名，供输入时联想 |
| `sw.js` | Service Worker，cache-first 离线策略 |
| `manifest.json` | PWA 清单 |
| `icons/` | 应用图标：矢量设计稿（`.svg`）+ 各尺寸 PNG，无外部依赖 |

## 本地预览

```bash
python3 tools/devserver.py
```

浏览器打开 <http://localhost:8080>。`localhost` 属于安全上下文，Service Worker 和 PWA 安装都能正常工作。这个脚本比 `python3 -m http.server` 多做一件事：明确关掉 HTTP 缓存，本地反复改代码测试时不会遇到「明明改了但页面没更新」（下面「更新机制」一节详细说明了原因）。

进「设置 → 载入示例数据」可以灌一批样例流水，立刻看到各页面的效果。

## 装到 iPhone

Service Worker 要求 **HTTPS**（`localhost` 除外），所以需要先传到一个带 HTTPS 的静态托管。GitHub Pages 最省事：

```bash
git init && git add -A && git commit -m "init"
git branch -M main
git remote add origin git@github.com:<你的用户名>/<仓库名>.git
git push -u origin main
```

然后仓库 **Settings → Pages → Source 选 `main` 分支根目录**，等一两分钟拿到 `https://<用户名>.github.io/<仓库名>/`。

在 iPhone 上：

1. **Safari**（必须是 Safari，Chrome 不行）打开该地址
2. 底部 **分享 → 添加到主屏幕**
3. 从主屏图标启动 —— 全屏无地址栏，之后**开飞行模式也能用**

⚠️ **主屏图标是"添加到主屏幕"那一刻的快照**，之后哪怕我把图标文件换了、Service Worker 也更新了，iOS 也不会主动帮你换掉桌面上已经生成的那个图标——这是所有 PWA/网页 App 在所有系统上的通用行为，不是本项目的 bug。**换图标之后要看到新图标，必须删除主屏上的旧图标、重新走一遍「添加到主屏幕」。**

## 更新机制

离线能力的代价是：代码更新之后，App 不会自动知道自己该换新版本。`sw.js` 做了这几件事让更新尽量顺畅：

- **`updateViaCache: 'none'`** 注册 —— `sw.js` 自身永远不走 HTTP 缓存，每次打开都会真的问一次服务器有没有新版本，不会出现「版本号明明改了，浏览器却一直觉得没变」
- **新版本装好会自动刷新页面一次**（监听 `controllerchange`），不用手动再刷
- **设置里有「检查更新 · 清除缓存并重新加载」按钮**，注销 Service Worker + 清空所有缓存 + 强制重载，任何一次更新如果没生效，点这个就行

正常用（比如从 GitHub Pages 装到手机主屏）基本不会碰到问题。真遇到更新卡住的情况（比如上面那个按钮本身也是旧版本、还没更新到），最后的手段是浏览器 DevTools → Application → Service Workers → Unregister，再 Application → Storage → Clear site data，然后强制刷新。

## Logo / 图标

[icons/logo-any.svg](icons/logo-any.svg) 是设计源文件（矢量，深色渐变背景 + 一条绿色渐变趋势线，末端一个发光圆点，标志"记录 + 上涨"）。`icons/logo-maskable.svg` 是同一版设计但内容缩小并居中，留出安全边距，专门给 Android/桌面 PWA 的圆形裁切用（W3C maskable icon 规范：内容要留在居中 80% 直径的圆内，不然被裁切成圆形时四角/边缘的东西会被切掉）。

用 [`@resvg/resvg-js`](https://github.com/thx/resvg-js) 从这两份矢量图光栅化出全部 PNG：

| 文件 | 尺寸 | 用途 |
|---|---|---|
| `apple-touch-icon.png` / `-120.png` / `-152.png` / `-167.png` | 180 / 120 / 152 / 167 | iOS 主屏（不同机型分辨率），必须**完全不透明**（已用 Pillow 验证过 alpha 全部是 255，没有透明像素） |
| `icon-192.png` / `icon-512.png` | 192 / 512 | `manifest.json` 里 `purpose: "any"` |
| `icon-maskable-192.png` / `icon-maskable-512.png` | 192 / 512 | `manifest.json` 里 `purpose: "maskable"`，Android 圆形/圆角裁切安全 |
| `favicon-32.png` / `favicon-16.png` | 32 / 16 | 浏览器标签页图标 |

想改设计：直接编辑 `icons/logo-any.svg`（或连着 `logo-maskable.svg` 一起改，两份内容除了缩放/居中的 `<g transform>` 之外应保持一致），然后重新跑一遍光栅化脚本导出全部尺寸——没有把这个脚本收进仓库里（只是个一次性工具），需要的话找我重新生成就行。

## 股票代码选择

记一笔时，代码框是**可搜索下拉**，三种输入方式都能命中：

| 输入 | 结果 |
|---|---|
| `AAPL` / `aapl` | 苹果（代码，大小写不敏感，自动转大写） |
| `苹果` | AAPL（中文名） |
| `apple` | AAPL（英文名） |
| `半导体` | SMH、SOXX、ADI、AMD…（模糊匹配，分类词也能搜） |

选中后自动填充中文名。排序优先级：代码全等 > 代码前缀 > 中文前缀 > 英文前缀 > 英文词首 > 各类包含匹配，同档内按代码字母序保证结果稳定。

代码框为空时会先列出**你最近交易过的标的**（持仓中的带「持仓」标记），没有记录时列热门股。

`stocks.js` 收录 299 支：美股大盘股、明星科技股、中概股、主流 ETF（宽基 / 行业 / 债券 / 商品 / 杠杆 / 比特币）。**库里没有的代码直接手输即可正常保存**，不做限制。要增删改直接编辑 `stocks.js`，格式是每行 `代码|中文名|英文名`。

## 热门行情（价格变动，不是走势图）

「持仓」页底部有一块**热门行情**，精选 23 支高关注度标的（`app.js` 里的 `HOT` 数组），跟持仓完全独立——没买过也能看。

这不是接了行情 API 拉实时数据，**依然是纯离线**：点一条 → 手动填最新价 → 保存。App 会记住你**上一次**填的价格，两次一比就是涨跌幅，用 ▲/▼ 加百分比标出来，红涨绿跌（呃，是绿涨红跌，美股习惯）：

```
NVDA  英伟达          $132.40
      更新于 2026-09-03      ▲ 3.15%
```

同一天反复改同一个数值不会把涨跌记录抹掉——只有价格**真的变了**才会把当前值滚动成「上一次」。持仓列表里每支股票下面也带了同样的涨跌角标。

想换成自己关注的股票，直接编辑 `app.js` 里的 `HOT` 数组（任意增删，建议保持在 `stocks.js` 库里有收录的代码，否则只显示代码没有中文名）。

**顺序可以拖拽调整**：每行右边有个 `⠿` 手柄，按住拖动就能重新排位置，松手自动存下来，下次打开还是你排好的顺序。这个顺序单独存在设置里，跟 `HOT` 数组本身没关系——以后我往 `HOT` 里加新代码（比如加 SpaceX 那次），会自动追加到你已排好的顺序最后面，不会打乱你排的位置；如果哪天从 `HOT` 里删掉了某支代码，它也会自动从你存的顺序里消失，不会留着变成幽灵条目。

### 联网自动刷新（可选）

默认还是上面说的纯离线手动模式。如果想要「自动变动」而不是每次手输，可以在**设置 → 行情自动刷新**里填一个免费 Key，然后点「持仓」页的**刷新行情**按钮联网拉真实的当日涨跌：

1. 打开 [finnhub.io/register](https://finnhub.io/register)，免费注册（不用信用卡），拿到一个 API Key
2. App 里「设置 → 行情自动刷新」粘贴 Key → 保存
3. 「持仓」页点「刷新行情」——一次性把热门行情 + 你实际持有的股票全部刷新，涨跌幅算的是真实的**当日对比昨收**，不是我们自己攒的手动记录

选用 [Finnhub](https://finnhub.io) 是因为它**原生支持浏览器跨域请求**（实测 `Access-Control-Allow-Origin: *`），不需要经过任何第三方代理中转，而且**免费层没有「每日总量」限制**——这条是专门换过的：最早接的是 Twelve Data，能用但免费额度每天 800 次封顶；找了一圈发现 Stooq 那种不需要 key 的免费源已经被反爬虫的加密验证挡死了（连 curl 都过不去），Yahoo Finance 数据更全但完全没有 CORS 响应头，浏览器直接拦，必须过代理，而试过的两个免费代理一个连不上、一个已经改成只认付费用户——权衡下来 Finnhub 是目前免费方案里同时满足「浏览器直连」和「不限每日总量」的选择。

- **免费额度**：不限每日总量，只按**每分钟 60 次**限速——对个人手动点刷新的用法基本感觉不到限制
- **代价**：免费版 `/quote` 一次只能查一个代码，刷新一批（约 20~30 支）要顺序逐个请求，中间留了 200ms 间隔，全部刷完大概 5~6 秒
- **只发代码**：请求里只有股票代码，不会带你的持仓、交易记录或任何金额
- **可选的自动刷新**：设置里勾选「打开 App 时自动刷新」，每次冷启动最多刷一次（15 分钟内重复打开不会重复刷）
- **不影响离线能力**：不填 Key，App 一直是 100% 离线的；填了 Key 也只有你主动点刷新（或打开 App）才会联网，绝不在后台偷偷轮询
- **失败时的行为**：Key 无效 / 断网 / 被限速，都会弹出具体原因的提示并立即停止（不会对着一个错误的 Key 把每支代码都白白试一遍），不会崩，也不会用假数据覆盖你已有的价格记录

## 主题

设置 → 外观，三选一：**跟随系统**（默认）/ **浅色** / **深色**。全部颜色都走 CSS 变量（`--bg`、`--fg`、`--up`、`--down`……），切换主题就是整批换一套变量值，不用一个个组件去改。

- 选了「跟随系统」的话，系统切换深浅色（比如晚上开了 iOS 的深色模式）App 会跟着实时变，不用重开
- 选了「浅色」或「深色」就固定住，不再跟系统联动
- 选择记在设置里（跟行情 Key 那些配置一起，存在 IndexedDB），同时也镜像一份到 `localStorage`——这是为了避免刚打开页面时先闪一下默认深色、脚本加载完才切换成你选的浅色，那一下闪烁很难看，用 `localStorage` 能在样式生效前就同步好

## 数据安全

数据存在本机浏览器的 IndexedDB 里。要注意：

- ✅ 添加到主屏的 Web App 有独立的使用天数计数，**不受 Safari「7 天未访问清除存储」策略约束**
- ⚠️ **删除主屏图标会连同数据一起清除**
- ⚠️ 系统存储极度紧张时，理论上仍可能被回收

所以「设置 → 导出为 JSON 文件」不是可选功能。iOS 上会调起系统分享面板，选「存储到文件」即可存进 iCloud Drive。换机或误删后用「从 JSON 文件导入」恢复。**建议每次记完一批交易顺手导一次。**

## 盈亏口径

- **买入手续费**摊进每股成本；**卖出手续费**从每股收入里扣除
- **已实现盈亏**按 FIFO 逐批匹配：卖出时依次冲抵最早的买入批次，一笔卖出可能拆成多条平仓记录（对应不同成本的批次）
- **浮动盈亏** = 持仓股数 × 现价 − 剩余成本。**未设现价的持仓浮动盈亏计为 0**，不会用成本价冒充市价
- **总收益率** = （已实现 + 浮动）÷（当前持仓成本 + 已平仓部分的成本）
- **盈亏比** = 平均盈利 ÷ 平均亏损（按笔，不是总额比）
- 若卖出股数超过已记录的买入（缺建仓流水），该部分按零成本计入并标记 `缺建仓`，不会静默算错

## 测试

- **FIFO 推导** 31 项断言：基础批次匹配、手续费摊销、未设价处理、卖出后买回的批次顺序、超卖标记、持仓天数、多标的汇总与百分比口径、金额格式化
- **代码搜索** 25 项断言：代码 / 中文 / 英文三种输入、分类词模糊匹配、排序优先级、库外代码放行
- **涨跌计算** 10 项断言：无记录 / 首次设价 / 涨跌幅计算 / 防除零、以及价格滚动逻辑（同值不覆盖历史、真变化才滚动）
- **行情接口解析** 9 项断言：正常报价、代码不存在时 Finnhub 返回全 0（识别为无效而非真实价格 0）、价格为负 / 昨收为 0 / 字符串数字等异常输入全部不崩溃、不误算
- **热门行情排序** 7 项断言：默认顺序、拖拽后的自定义顺序、新加代码自动补末尾、删掉的代码自动从存的顺序里滤掉、脏数据 / 非法值不崩溃

## 已知取舍

- **默认不联网**，行情靠手动填。想要自动变动就配一个免费的 Finnhub Key（见上）；不配就一直手动，两种模式随时切换，互不冲突。已实现盈亏永远不依赖现价，无论哪种模式都准确。
- 暂不支持股票拆分、分红、多币种、期权。
